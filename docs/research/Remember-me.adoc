= Research: “Remember Me” Session Persistence for the UPRM Lost & Found Platform
Author: Angel Villegas
Date: February 2026


== 1. Introduction

This research evaluates the implementation of a “Remember Me” functionality for the UPRM Lost & Found platform.

A “Remember Me” feature allows users to remain signed in across browser sessions without re-entering credentials. While this improves usability, it introduces security considerations that must be carefully evaluated.

This document analyzes session persistence strategies, Firebase Authentication support for persistent sessions, associated risks, and recommendations aligned with the platform’s security objectives.

== 2. Session Persistence Requirements

The platform requires:

* Secure user login and logout
* Configurable session duration
* Protection against unauthorized access on shared devices
* Secure handling of authentication tokens
* Integration with Firebase Authentication

The solution must balance convenience and security.

== 3. How “Remember Me” Works

The “Remember Me” functionality extends the lifetime of a user session by storing authentication state across browser restarts.

Modern authentication systems typically use:

* ID tokens for authentication
* Refresh tokens for session renewal
* Secure cookies or browser storage to maintain login state

When “Remember Me” is enabled, authentication tokens are stored in persistent storage. When disabled, session data is cleared when the browser closes.

== 4. Firebase Authentication Session Options

Firebase Authentication provides built-in session persistence modes for web applications:

* *Local* – The user remains signed in even after closing and reopening the browser.
* *Session* – The user remains signed in only while the tab is open.
* *None* – The user must log in again after refresh or reload.

These persistence settings can be configured programmatically, allowing the application to simulate a “Remember Me” checkbox.

Firebase automatically manages ID and refresh tokens, reducing backend complexity and minimizing manual session handling.

== 5. Security Considerations

While persistent sessions improve user experience, they introduce potential risks.

=== 5.1 Shared Devices

If a user enables “Remember Me” on a public or shared computer, unauthorized users may gain access.

Mitigation:

* Provide clear warnings on shared devices.
* Offer session-only persistence as default in sensitive environments.

=== 5.2 Token Theft

If tokens stored in browser storage are compromised, attackers may hijack sessions.

Mitigation:

* Enforce HTTPS for all communications.
* Rely on Firebase’s secure token lifecycle management.
* Avoid exposing tokens in insecure storage mechanisms.

=== 5.3 Session Expiration

Long-lived sessions increase exposure time.

Mitigation:

* Use reasonable token expiration times.
* Allow manual logout.
* Invalidate sessions upon password changes.

Proper configuration significantly reduces these risks.

== 6. Usability vs Security Trade-Off

Persistent login sessions:

* Improve user convenience.
* Reduce login friction.
* Enhance user retention.

However:

* Increase exposure risk on shared devices.
* Require careful session management.

A configurable persistence option allows users to choose based on their environment.

== 7. Recommendations

For the UPRM Lost & Found platform, the recommended approach is:

* Implement a “Remember Me” checkbox during login.
* Use Firebase local persistence when enabled.
* Use session persistence when not enabled.
* Enforce HTTPS and secure token handling.
* Provide clear logout functionality.

This approach balances usability and security while leveraging Firebase’s built-in session management.

== 8. Conclusion

A “Remember Me” feature enhances user experience by allowing persistent login sessions.

Firebase Authentication provides secure, configurable session persistence mechanisms that align with the platform’s needs.

With proper configuration and security controls, persistent sessions can be implemented safely and effectively.
