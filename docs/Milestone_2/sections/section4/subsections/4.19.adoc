==== Domain Description Units for Lost & Found
:author: Abdiel Cotto

=== Definition of Domain Description Units

A domain description unit (DDU) is a small, source-traceable statement that captures one domain fact at a time. Each unit isolates a single fact and tags it with metadata so the fact can be analyzed, reviewed, compared, and reused without mixing several ideas together.

For this Lost & Found system, each DDU includes:

- `ID` for traceability
- `Stakeholder source` showing where the fact came from
- `Kind` to classify the fact as an `entity`, `function`, `event`, or `behavior`
- `Attribute` to indicate whether the fact is mainly `passive`, `active`, or `reactive`
- `Facet classification` to group the fact by domain concern
- `Fact` as the atomic domain statement

=== Why Structuring Helps Domain Understanding

Structuring domain knowledge into DDUs improves understanding because each fact becomes atomic, explicit, and traceable. Instead of mixing concepts such as reports, verification, and recovery in one paragraph, the team can review each fact separately, classify it consistently, and check whether it belongs to the domain, the requirements, or the implementation.

This also makes disagreements easier to detect. If a stakeholder challenges a fact, the team can point to the exact DDU, its source, and its classification instead of revisiting an entire narrative section. As a result, DDUs support clearer analysis, better requirement derivation, and stronger documentation consistency.
