==== *Interface Requirements*

|===
| ID | Description | Linked User Stories/Epics | Verification Tests

| IR001
| The system must provide a structured form during registration for new recruiters to initialize their profile (capturing company name, professional email, and job role).
| US-Auth-002: Register as Recruiter
| T-UI-010, T-FE-001

| IR002
| All interfaces must adapt seamlessly to desktop, tablet, and mobile viewports (mobile-responsive design).
| All features (university students use mobile devices)
| T-UI-011, T-RES-001

| IR003
| The UI must consistently utilize the university color scheme and logo placement across all pages.
| Branding Guidelines
| T-UI-012

| IR004
| All interfaces must comply with WCAG 2.1 AA standards for accessibility.
| Accessibility Standards
| T-ACC-001, T-ACC-002

| IR005
| The homepage must include a search bar, featured recent items, a statistics overview, and a call-to-action to log in.
| II. Search and Discovery, VI. Dashboard and Analytics
| T-HP-001, T-SRCH-001

| IR006
| The system must provide a public view for item details showing only public fields (category, description, photos, general location) and a prompt to log in to contact the owner.
| III. Report and Object Management, Secure data handling
| T-DET-001, T-AUTH-003

| IR007
| The login page must initiate the UPR.edu authentication redirect and inform users about required access for interactions.
| I. User Access and Authentication
| T-AUTH-001, T-AUTH-002

| IR008
| The authenticated user dashboard ("My Reports") must display tabs for Lost Reports, Found Reports, and Messages, along with quick stats.
| III. Report and Object Management, IV. Communication System, VI. Dashboard and Analytics
| T-DASH-001, T-MSG-001

| IR009
| Report creation forms (Lost/Found) must include structured fields with validation, such as category dropdown, description, location picker, photo uploader, and private fields.
| III. Report Creation, VII. Categorization System
| T-FE-002, T-VAL-001

| IR010
| The messaging interface must include an inbox view with conversation previews and a conversation view with a message thread and reply box.
| IV. Communication System
| T-MSG-002, T-MSG-003

| IR011
| The admin panel must include a dashboard with key metrics, a reports queue for moderation, user management, and system logs.
| V. Administrative and Moderation System
| T-ADMIN-001, T-MOD-001

| IR012
| The system must provide a RESTful API with JSON payloads, using JWT tokens obtained via UPR.edu OAuth for authentication.
| I. User Access and Authentication
| T-API-AUTH-001

| IR013
| An API endpoint `GET /api/v1/reports` must be available to list reports with support for query parameters for filtering.
| II. Search and Discovery System
| T-API-RPT-001

| IR014
| An API endpoint `POST /api/v1/reports` must be available to create a new report (Lost/Found type).
| III. Report Creation
| T-API-RPT-002

| IR015
| An API endpoint `GET /api/v1/search` must be available for unified searching with query and filter parameters.
| II. Search and Discovery System
| T-API-SRCH-001

| IR016
| An API endpoint `POST /api/v1/uploads/images` must be available to upload images, returning a URL for the stored image.
| Image upload system requirement
| T-API-IMG-001

| IR017
| The system must implement event-driven communication between backend services (Auth, Report, Search, Notification, Moderation, Analytics) to handle processes like notifications and analytics.
| Match notifications, Status changes
| T-EVT-001, T-NOT-001

| IR018
| The system must integrate with an email service to send transactional emails using predefined templates (e.g., match notification, new message alert).
| VIII. Notification System
| T-EMAIL-001
|===
