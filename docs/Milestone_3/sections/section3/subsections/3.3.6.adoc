==== Example User Scenarios for the Lost & Found System

This section describes example user interaction scenarios for the Lost & Found system. These scenarios illustrate common behaviors within the platform, including reporting lost items, posting found items, submitting claims, and reviewing claims.

===== Introduction

The Lost & Found system supports multiple types of user interactions related to reporting, searching, and recovering items. The following scenarios present common flows that help define how users and administrators are expected to interact with the system.

===== [.changed]#Scenario 1: Reporting a Lost Item#

*Actor:* User

. A user logs into the Lost & Found platform.
. The user selects "Report Lost Item."
. The user enters item details such as description, location, and date lost.
. The system saves the lost item report and makes it searchable.

*Result:* The lost item is stored in the system and can later be matched with found items.

===== [.changed]#Scenario 2: Admin Reviews a Claim#

*Actor:* Administrator

. The administrator reviews submitted claim requests.
. The administrator verifies the claim information.
. The administrator decides whether the claim is valid.
. The claim is approved or rejected.

*Result:* If approved, the item can be returned to the owner.

===== [.changed]#Scenario 3: User Creates an Account#

*Actor:* User

. The user enters account details at the sign-up page.
 .. If the email is not a UPR email address, an error is shown. The user remains in the sign-up page.
 .. If the email is a UPR email address, it is validated and the account is created.
. The user enters the newly-created account credentials at the login page.
 .. If the account credentials are valid/correct, the user is logged in successfully.
 .. If the account credentials are not valid/correct, the user is shown an error message and remains in the login page. 

*Result:* User has an account and access to the platform's features.

===== [.added]#Scenario Validation Considerations#

[.added]#The following validation requirements and edge cases should be considered when implementing the documented workflows.#

====== [.added]#Reporting a Lost Item#

[.added]#Preconditions:#

* [.added]#User is authenticated.#
* [.added]#Required item information is available.#
* [.added]#The report contains a valid date and description.#

[.added]#Potential failure cases:#

* [.added]#Missing required fields.#
* [.added]#Invalid date values.#
* [.added]#Duplicate reports for the same item.#
* [.added]#Network interruption during submission.#

====== [.added]#Posting a Found Item#

[.added]#Preconditions:#

* [.added]#User is authenticated.#
* [.added]#Item details can be reasonably described.#

[.added]#Potential failure cases:#

* [.added]#Missing location information.#
* [.added]#Incomplete item descriptions.#
* [.added]#Invalid submission data.#
* [.added]#Duplicate found-item listings.#

====== [.added]#Submitting an Item Claim#

[.added]#Preconditions:#

* [.added]#Matching item listing exists.#
* [.added]#User is authenticated.#

[.added]#Potential failure cases:#

* [.added]#Claim submitted for an unrelated item.#
* [.added]#Missing ownership evidence.#
* [.added]#Duplicate claim requests.#
* [.added]#Item already returned to another user.#

====== [.added]#Reviewing a Claim#

[.added]#Preconditions:#

* [.added]#Administrator privileges are available.#
* [.added]#Claim information has been submitted.#

[.added]#Potential failure cases:#

* [.added]#Insufficient ownership evidence.#
* [.added]#Incomplete claim information.#
* [.added]#Conflicting claim requests.#
* [.added]#Administrative processing errors.#

====== [.added]#User Account Creation#

[.added]#Preconditions:#

* [.added]#User has access to a valid UPR email address.#
* [.added]#Required registration information is available.#

[.added]#Potential failure cases:#

* [.added]#Invalid UPR email address.#
* [.added]#Email already registered.#
* [.added]#Missing required account information.#
* [.added]#Authentication service unavailable.#

====== [.added]#Expected Validation Outcomes#

[.added]#The system should reject incomplete submissions, notify users when validation fails, and preserve data consistency throughout all item lifecycle operations.#
