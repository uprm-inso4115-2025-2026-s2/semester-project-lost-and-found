==== Risk Analysis for the Lost & Found System
:author: Fabian Acevedo (@FabianAcevedo1)

The Lost & Found system allows users with UPRM accounts to report lost items, search reports, and contact other users to recover their items.
Since the app involves user-generated content, personal contact information, and file uploads, there are several risks that may arise and affect
the reliability, usability, and security of the platform. This document identifies possible risks, evaluates their likelihood and impact
and provides mitigation strategies.

===== Incorrect or False Reports
Likelihood: High
Impact: Medium
A user may submit a report with incorrect information about an item (wrong location, description, or fake report).

Mitigation Strategy:
- Require structured input fields when creating a report
- Allow users to update or delete reports
- Include report timestamps and categories to help with verification

===== Malicious File Uploads
Likelihood: Medium
Impact: High
A user could try to upload non-image files like a .exe or .mp3 where an image should go.

Mitigation Strategy:
- Restrict accepted file formats to .png and .jpeg
- Implement file validation in both frontend and backend

===== Unauthorized Access to Contact Information
Likelihood: Medium
Impact: High
Users without a UPRM account could attempt to access the contact information of report creators.

Mitigation Strategy:
- Implement a View Only mode for users without a UPRM account
- Hide user contact information unless the viewer has a UPRM account
- Require login with a verified UPRM account to interact with reports

===== Report Status Inconsistency
Likelihood: Medium
Impact: Medium
A report may incorrectly remain marked as “Lost” even after the item has been claimed or returned.

Mitigation Strategy:
- Provide clear status categories (Lost, Claimed, Returned)
- Ensure backend updates are synchronized with the UI

===== Duplicate Reports
Likelihood: High
Impact: Low
Multiple users may submit reports for the same item, causing confusion.

Mitigation Strategy:
- Provide tags and search features to check existing reports
- Encourage detailed descriptions and images

===== Main Goals and subgoals derived from the main goal:
====== *Goal 1* :Successful Report Creation
*Subgoals:*

- Users can report lost or found items

- Users can upload images of the items(optional)
- Users can input important report details such as: location, date, item category
- Reports are saved and submitted without complications

*Goal Negation:*
    Reports are not successfully created

====== Countermeasures for major obstacles
a) Obstacle: Incomplete item descriptions
Category: Inaccuracy Obstacle
Countermeasures:

- Require mandatory description fields and provide examples or templates for users

b) Obstacle: Users upload inappropriate images
Category: Threat Obstacle
Countermeasures:

- Implement image moderation, file validation, reporting mechanisms, admin reviews and deletion of inappropriate posts

c) Obstacle: Users abandon report creation before submission
Category: Dissatisfaction Obstacle
Countermeasures:

- Enable auto save drafts and simplify the reporting interface

d) Obstacle: Incorrect item category selection
Category:Inaccuracy Obstacle
Countermeasures:

- Provide predefined categories with  clear suggestions 

e) Obstacle: Server failure during submission
Category:Hazard Obstacle
Countermeasures:

- Use backup storage and confirmation messages

f) Obstacle: Duplicated reports
Category:Misinformation Obstacle
Countermeasures:

- Detect similar reports using item details and notify users before submission

g) Obstacle: Users enter false information
Category: Threat Obstacle
Countermeasures:

- Require authentication with university credentials and allow report verification

h) Obstacle: Missing description, location, or date
Category: Misinformation Obstacle
Countermeasures:

- Make critical fields mandatory before submission

====== *Goal 2* : Secure and Reliable user access:
*Subgoals:*

- Users can authenticate with university(uprm) credentials
- Unauthorized access is prevented
- User data and sensitive information remains private
- Platform remains available during peak usage
- Reports are stored reliably. 


*Goal Negation:*
    Unauthorized users gain access and sensitive user data becomes compromised

====== Countermeasures for major obstacles

a) Obstacle:Weak password security
Category: Threat Obstacle
Countermeasures:

- Enforce strong password policies and secure authentication protocols such as multi-factor authentication


b) Obstacle:Unauthorized system access
Category: Threat Obstacle
Countermeasures:

- Implement role-based access control and secure login validation

c)Obstacle: Server overload during peak usage
Category: Hazard Obstacle
Countermeasures:

- Use scalable cloud infrastructure and load balancing

d) Obstacle: Data breach or privacy leak
Category: Threat Obstacle
Countermeasures:

- Encrypt sensitive data and follow secure database practices

e) Obstacle: Authentication service failure
Category: Hazard Obstacle
Countermeasures:

- Add backup authentication methods and monitoring systems
