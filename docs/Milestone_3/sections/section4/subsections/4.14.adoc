==== Risk Analysis for the Lost & Found System
:author: Fabian Acevedo (@FabianAcevedo1)

The Lost & Found system allows users with UPRM accounts to report lost items, search reports, and contact other users to recover their items.
Since the app involves user-generated content, personal contact information, and file uploads, there are several risks that may arise and affect
the reliability, usability, and security of the platform. This document identifies possible risks, evaluates their likelihood and impact
and provides mitigation strategies.

===== Incorrect or False Reports
Likelihood: High
Impact: Medium
A user may submit a report with incorrect information about an item (wrong location, description, or fake report).

Mitigation Strategy:
- Require structured input fields when creating a report
- Allow users to update or delete reports
- Include report timestamps and categories to help with verification

===== Malicious File Uploads
Likelihood: Medium
Impact: High
A user could try to upload non-image files like a .exe or .mp3 where an image should go.

Mitigation Strategy:
- Restrict accepted file formats to .png and .jpeg
- Implement file validation in both frontend and backend

===== Unauthorized Access to Contact Information
Likelihood: Medium
Impact: High
Users without a UPRM account could attempt to access the contact information of report creators.

Mitigation Strategy:
- Implement a View Only mode for users without a UPRM account
- Hide user contact information unless the viewer has a UPRM account
- Require login with a verified UPRM account to interact with reports

===== Report Status Inconsistency
Likelihood: Medium
Impact: Medium
A report may incorrectly remain marked as “Lost” even after the item has been claimed or returned.

Mitigation Strategy:
- Provide clear status categories (Lost, Claimed, Returned)
- Ensure backend updates are synchronized with the UI

===== Duplicate Reports
Likelihood: High
Impact: Low
Multiple users may submit reports for the same item, causing confusion.

Mitigation Strategy:
- Provide tags and search features to check existing reports
- Encourage detailed descriptions and images

==== [Lecture Topic Task] Goal Diagram For Returning Lost Items
:author: Andrés Cruz

===== Introduction
This diagram models the potential risks when returning an item and the countermeasures that can be taken to minimize the risks and increase the chances of an item being returned to its rightful owner.

image::RiskModelingDiagram.png[Risk Modeling Diagram, align=center, pdfwidth=80%]

===== Event
* Name: Lost/Found Item Reported
** Def: Item is registered into the system.

* Name: Item Match Found
** Def: User claims a reported item.

* Name: Owner Notified
** Def: Loser receives a claim notification when claiming an item or receives a notification when their item is found.

===== Risks
* Name: Incomplete Description
** Def: Report lacks information such as description, location or category.

* Name: Duplicate Report Filed
** Def: Reports of the same type that cover the same lost item.

* Name: Category Mismatch
** Def: Categories are filed inconsistently or do not correspond to the item in the report.

* Name: Missing Contact Info
** Def: User does not have valid identification to verify identity before claiming an item.

===== Countermeasures
* Name: Mandatory Info
** Def: Have fields such as title, location, description, and category as mandatory fields.

* Name: Automatic Duplicate Detection
** Def: Compare a new report to existing reports to find similarities before registering the new report.

* Name: Guided Category Setting
** Def: Have a structured category system such as a dropdown menu to avoid ambiguous and inconsistent categories.

* Name: Claim Code Verification
** Def: Provide a claim code once a user claims a lost item to verify claimer identity when retrieving a lost item.
